# Урок 38 — Розбір і оптимізація мініпроєкту

## Завдання

> Порефакторити код мініпроєкту, котрий ми написали на уроці спільно.

На відміну від уроку 37, тут тільки рефакторинг — без задач на вибір.

## Що зроблено

Урок 37 був першим проходом: виправити баги в одному файлі. Тут другий —
розкласти по модулях, щоб `main.c` містив логіку, а не налаштування периферії.

```
main/
├── main.c      — тільки сценарій: прочитати → згладити → перевести в кут → віддати
├── ldr.h/.c    — ADC і калібрування
├── servo.h/.c  — LEDC і перетворення кута в duty
└── sma.h/.c    — фільтр
```

### Виправлені помилки вихідного коду

**Обчислення duty було неточне.** Було `(uint32_t)(4095 / 20) * val_us / 1000` —
цілочисельне `4095 / 20` дає 204 замість 204.75, похибка 0.37% у кожному куті.
Плюс числа вписані руками, тож зміна розрядності мовчки зламала б формулу.
Стало `pulse_us * SERVO_MAX_DUTY / SERVO_PERIOD_US` — множення перед діленням.

**Макрос без дужок.** `#define SERVO_PERIOD_MS 1000/SERVO_FREQ` підставляється
текстом, тому в будь-якому виразі з діленням дає не те. Тепер
`SERVO_PERIOD_US` у дужках.

**`adc_oneshot_read()` викликався без перевірки** — загорнуто в `ESP_ERROR_CHECK`.

### Решта змін

- `printf` для налагодження → `ESP_LOGI` / `ESP_LOGD`
- глобальні `adc_handle` / `cali_handle` стали `static` всередині `ldr.c`
- «калібрувальні» `static int`, які ніколи не змінювались, стали `#define`
- закоментовані блоки `ADT Test` і `SERVO Test` прибрані
- додана ковзна середня, яку вихідний код позначав як TODO у кінці файлу

### Чому фільтр зі станом у структурі

У версії 37 ковзна середня трималася на глобальних змінних — один фільтр на всю
програму. Тут `sma_t` передається аргументом, тому фільтрів може бути скільки
завгодно і вони не заважають одне одному. Додати другий сенсор тепер нічого не
ламає.
