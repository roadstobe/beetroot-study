## Частина 1. Рефакторинг

Вихідний код працював, але мав кілька місць, які або вже баг, або стануть ним.

### Обчислення duty було неправильне

Було:

```c
// uint32_t duty = (uint32_t)(SERVO_MAX_DUTY / SERVO_PERIOD_MS) * val_us / 1000;
uint32_t duty = (uint32_t)(4095 / 20) * val_us / 1000;
```

Тут дві проблеми. По-перше, числа 4095 і 20 вписані руками — зміни
`SERVO_RESOLUTION` на 10 біт, і формула мовчки почне брехати. По-друге,
`4095 / 20` — це цілочисельне ділення, дає 204 замість 204.75. Помилка 0.37%
тягнеться в кожне значення кута.

Стало:

```c
uint32_t duty = (uint32_t)pulse_us * SERVO_MAX_DUTY / SERVO_PERIOD_US;
```

Множення йде **перед** діленням, тому точність не втрачається. Максимум
`2500 × 4095 = 10 237 500` — у 32 біти влазить із запасом.

### Макрос без дужок

```c
#define SERVO_PERIOD_MS  1000/SERVO_FREQ
```

Підставляється текстом, тому `100 / SERVO_PERIOD_MS` розкривається у
`100 / 1000 / 50` — не те, що очікуєш. Замінено на `SERVO_PERIOD_US` у дужках.

### Решта

- `printf` для налагодження → `ESP_LOGI` / `ESP_LOGD`, рівень вимикається без правки коду
- глобальні `adc_handle` / `cali_handle` → `static`, не стирчать назовні
- `adc_oneshot_read()` викликався без перевірки результату — загорнуто в `ESP_ERROR_CHECK`
- «калібрувальні» `static int`, які ніколи не міняються, стали `#define`
- закоментовані шматки SERVO Test і ADT Test прибрані
- `mad_map` → `map_range`, `val_clamp` → `clamp`
- додана ковзна середня, яку вихідний код позначав як TODO у кінці файлу

## Частина 2. Калькулятор

### Схема

```
GPIO10 ── A    ┐
GPIO11 ── B    ├─ енкодер EC11
GPIO12 ── SW   ┘
GND    ── C / GND
```

### Сценарій

```
234  →  234 +  →  234 + 77  →  234 + 77 = 311
```

Обертання задає значення, натискання підтверджує і переводить на наступний
крок: перший операнд → операція (`+ - * /`) → другий операнд → результат.
Натискання на результаті починає новий приклад з нового рядка.

Рядок перемальовується на місці через `\b`: стираємо стільки символів,
скільки надрукували минулого разу, і друкуємо новий.

### Чому PCNT, а не читання пінів вручну

Енкодер підключений до апаратного лічильника імпульсів. Два канали налаштовані
навхрест: кожен рахує фронти на своєму піні, а напрям визначає за рівнем
сусіднього. Це і є квадратурне декодування, і робить його залізо, а не цикл.

`max_glitch_ns = 1000` — апаратний фільтр брязкоту. Імпульси коротші за
мікросекунду не рахуються взагалі, тому програмний дебаунс для обертання не
потрібен. Кнопка — інша річ, вона на звичайному GPIO, тому для неї дебаунс
зроблений у коді: рівень має протриматись 40 мс.

### Що може знадобитись підкрутити

`STEPS_PER_DETENT` стоїть 4 — стільки змін стану дає один клік типового EC11.
Якщо твій енкодер клацає інакше (буває 2), значення треба поміняти, інакше
один клік буде перескакувати через два числа або вимагати двох кліків.

Якщо обертання йде у зворотний бік — поміняй місцями `ENC_A_PIN` і `ENC_B_PIN`.
